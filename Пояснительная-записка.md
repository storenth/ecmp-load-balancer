## Пояснительная записка
### Топология и конфигурация
Статическая топология может быть создана с использованием QEMU/KVM CLI на базе Linux в случае собственных реализаций ядерных модулей.
Решение создано на базе Linux Network Namespace с использованием bash-скриптов, в основе идея о метриках/весах "nexthop weight 1".
### Генерация тестового трафика
- Развернут простой http echo-server на 80 порту DEST_IP
- Для генерации трафика достаточно ICMP пакетов `ping DEST_IP` и TCP-сессий `http://${DEST_IP}:80` с двух source-IP
### Методика захвата трафика
- Захват осуществляется на интерфейсах виртуального устройсва с функцией ECMP-роутера в сторону сети назначения с помощью `tcpdump`
### Анализ результатов
Для простоты верификацию можно сделать с использованием tshark: один и тот же IP не должен встречаться в обоих pcap-файлах.
В текущей версии проверяется:
- Source IP Hash Consistency - наличие SOURCE_IP_1 или SOURCE_IP_2 адреса на одном из путей PATH 1 или PATH 2
- Byte Distribution - степень отклонения
- Protocol Alignment - соответствие путь/протокол за счет `tshark`
### Отчет
Для отчета требуется составление тест-плана, например по стандарту ISO/IEC/IEEE 29119-3 чтобы
Финальный отчет содержал степень достижимости заявленым в плане целям, соответствию RFC 2991, 2992, 2544, 2330, результаты прогона и выводы на основе расширенных метрик (например Deviation, Entropy, Chi-square и др).
В данном решении мы получаем отчет о тестировании на stdout от analyze_results.sh
### Ограничения
- Создана статическая топология, для динамической рекомендуется использовать FRR
- Не ставилась задача о Resilient Hashing, Symmetric Hashing и др
- По умолчанию fib_multipath_hash_policy=0
